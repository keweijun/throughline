# Courses carry a schema version and migrate forward

Learners already have courses on disk, and courses move between computers by copying the folder (ADR 0004), and since ADR 0020 as course packages. Until now the course format changed implicitly: code read missing fields with fallbacks and "existing courses open without migration" (ADR 0003). That works for additive fields but not for reshaping stored data, backfilling a field that new features depend on, or protecting a course from an older app that does not understand it.

Each course workspace stores `course/schema` = `{"version": N}`. `guided_learning/migrations.py` holds an ordered list of migrations, each a function `(store) -> None` that moves the course from version N-1 to N. Courses without the record are version 1, the format before versioning.

- `execute` reads the version at the start of every operation, inside the operation's transaction. If it is older than the code's version it runs the pending migrations in order and records the new version before handling the request, under `BEGIN IMMEDIATE`, so a migration commits or rolls back with that first operation. (A read-only operation runs without the write lock; when it finds an older version it is run again as a write, so the migration still happens first.) `course.init` on a new course records the current version directly.
- A course whose version is newer than the code fails every operation with `course_too_new` and a message to update Throughline. An older app never writes to a newer course.
- Migrations only move data forward; there is no downgrade. They must be idempotent on partially migrated data, preserve learning evidence and raw interactions, and keep every operation's name and semantics (the stable contract in AGENTS.md).
- The course library lists such a course with that message instead of opening it. Listing a course runs its pending migrations like any other operation.
- Before the first migration step, the course is copied as it is to `backups/course-format-<N>.sqlite3` in the course folder, N being its version before migrating, with SQLite's backup API (through a second connection: SQLite refuses to back up through the connection that holds the write lock, and nothing is written before the copy). A backup of the same format that already exists is kept, since it is the one from before any attempt. If the copy cannot be made (a full disk, a folder that cannot be written), the course is not migrated and every operation fails with `backup_failed` until it can be. New and up-to-date courses, and courses refused as too new, are never copied. Backups are not course material: nothing registers, lists or teaches from `backups/`, and Studio's file search leaves them out.

Since migrations only move forward and an older Throughline refuses a migrated course, the backup is the way back from a migration that went wrong. To restore one: stop Throughline (`guided-learning stop`), install the Throughline version that wrote that format, replace the course's `course.sqlite3` with the backup (renamed to `course.sqlite3`), and delete `course.sqlite3-wal` and `course.sqlite3-shm` beside it if they exist. Whatever was studied after the migration is lost with it.

Each format from 7 on keeps a real course as a fixture, `tests/fixtures/courses/format-<N>.sql`: a course studied through the host with a scripted teacher by `tests/fixtures/make_course.py`, written by the code of that format and dumped as SQL. A test opens every fixture with the current code and checks that it migrates, loads and keeps its learning records, so a migration is tested against courses as learners left them, not only against records edited by hand. A change that adds a migration generates the fixture for the new format.

Copying a course to a computer with an older Throughline now gives a clear "update Throughline" error instead of silent misreads. The cost is one small read per operation and the discipline of writing a migration plus a test with an old-format fixture whenever stored data changes shape.

The first migration (version 2) replaces the whole lesson record that each side question copied into `selected_lecture`, and into every answer's prompt snapshot, with the lesson's id, section, title, text and source references.

Migration 7 moves frozen prompt snapshots and prepared material out of the turn and preparation job records into records of their own (ADR 0018).
