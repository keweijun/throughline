# 学习工作流优化建议

研究日期：2026-10-12（用户时区）。依据：已通读指定 Obsidian 对话，并查看关联学习路径及进度文件；产品部分核对官方文档和仓库，未安装实测。用户补充：使用过 DeepTutor Mastery Path，跨文档导学不满足需求，且遇到文档读取 bug。

## 判断

建议把课程地图、学习证据和教学对话分开管理，让后台模型维护笔记与材料，而前台教师围绕一个明确学习目标快速响应。Obsidian 保留为资料与笔记出口，学习交互可迁到专门界面。

现成产品中，RemNote 值得小规模体验；DeepTutor 保留为有条件候选；OpenMAIC 更适合互动课堂。如果必须可靠实现跨课件长程导学，当前查到的文档不足以证明任何一个候选已经完全满足，可能仍需一层独立的课程状态与调度。

## 对现有学习记录的诊断

1. **规划已经存在，执行约束不足。** 路径有 11 个阶段、前置技能和 L0–L4 标准。进度已到阶段 6，完整阶段与整道题的独立完成数仍是 0/11。记录没有虚报掌握，这是优点；但“待验证”长期积累，未有效改变下一步教学。
2. **先修缺口在推导之后才暴露。** 学习者两次追问态为什么是函数、自变量是什么；随后又问期望值公式和测量平均值的关系。说明需要在本征态、投影、厄米性之前加入短概念检查，并把未解决的疑问作为下一轮输入。
3. **节奏两端失衡。** 前面将简单动量和波长计算拆成多轮；后面连续“继续”后直接给出完整证明和题解。更合适的粒度是一个完整概念或解题步骤，允许“听讲 / 提示练习 / 独立测试”切换。
4. **后台事务进入可见教学。** 多轮出现读进度、核对更新资料、保存记录等文字，部分回答开头与正文重复，另有一次空回复。导出的文本不能确定重复由模型还是消息拼接导致，也不能证明文件操作占了多少延迟。
5. **覆盖尚不能审计。** 当前路径按文档和阶段映射，并保留“第二遍补齐”；没有逐页或小节的完整覆盖台账。不能据此宣称已经漏了某个特定知识点，但“有没有遗漏”难以核验。
6. **进度反馈过粗。** 0/11 对严格独立完成的定义合理，但不能表达已经学过什么。界面应分别显示讲解覆盖、实际作答、独立通过与待复习，避免把所有活动压成一个百分比。

聊天记录的相邻时间差包含用户阅读与离开时间，不能用作模型响应耗时；元数据里的 usedTokens 也不能直接当作每轮输入长度。

## 建议的工作流

### 导入时建立课程地图

先解析并缓存 8 份资料，保留原文件、页码/幻灯片号、公式和图像的来源位置。展示解析成功/失败清单；失败文件或页面必须可见，不允许静默略过。

将材料整理成三类关联：

- 知识点 ↔ 出现它的多个来源页面；重复讲解合并，来源全部保留。
- 知识点 → 先修知识点；例如概率幅、复共轭与内积支撑投影与测量。
- 每道题的每个小问 ↔ 所需知识点、方法与评分标准。

每个来源小节必须标为“已映射 / 有意暂缓 / 排除并注明理由 / 解析待修”。全文覆盖和掌握程度分别计算。普通语义检索只会找相关内容，不能自动证明课程完整。

首版可以用关系表或 JSON 表达这些连接，不需要先部署复杂图数据库。地图调整应保留版本，学习证据绑定稳定知识点 ID。

### 前台教师与后台任务分工

| 工作 | 执行时机 | 模型与状态原则 |
|---|---|---|
| 解释、追问、当前答题反馈 | 前台流式响应 | 使用足够可靠的教学模型；难推导才增加推理预算 |
| 保存原始问答与提交事件 | 同步快速写入 | 程序执行，无须 LLM |
| 提取偏好、误解、学习摘要 | 回答后后台执行 | 快模型输出结构化候选更新，保留证据来源 |
| 整理 Obsidian 笔记、复习卡 | 每个小节结束或空闲时 | 合并多轮处理，避免每句话重写大文件 |
| 材料补漏、下一节资料预取 | 后台/材料变更时 | 独立任务，不阻塞当前讲解 |
| 掌握度升级、下一步选择 | 当前证据可用后 | 规则校验；关键判定不能完全交给无审核摘要 |

主教师每轮只需当前目标、必要来源片段、相关先修状态、未解疑问、近期对话和最新用户输入。跨课题才检索更多历史。

后台更新应携带事件 ID、证据消息 ID 和状态版本；重复任务不能重复加分，旧摘要不能覆盖新答案。后台任务尚未完成时，教师仍读取最新原始事件；若评价未完成就保留“待评估”，不能直接放行。后台并发还要限流，避免抢占前台模型配额。

这种拆分有现成工程支撑：LangGraph 区分会话检查点与跨会话存储，并明确讨论前台与后台记忆更新的取舍。但课程知识图、掌握判定和后台队列规则仍需应用自己实现。[LangGraph 记忆文档](https://docs.langchain.com/oss/python/concepts/memory)

### 教学调度具体化

默认推进方式：一个目标 → 直觉或例子 → 必要公式 → 一个短检查 → 决定继续、补先修或进入练习。

“继续”表示继续当前教学模式，不构成掌握证据。“这次不算积分”允许跳过计算，但记录为该技能未测，并保留后续检查。用户也应能主动选择只听讲，界面清楚区分听过与通过。

每个知识点至少独立记录：讲解状态、概念理解证据、计算技能证据、提示程度、具体误解、下一次检查。对本次对话，“态与函数的关系”再次出现疑问，应触发概念补救；不能因科学计数法熟练而推断抽象概念也可以加速。

OATutor 值得借鉴其知识技能与掌握估计分离的设计：它使用 Bayesian Knowledge Tracing，现成内容偏数学，需要自行制作量子课程。首版可以先用透明等级规则，不必在作答数据很少时输出看似精确的掌握概率。[OATutor 官方仓库](https://github.com/CAHLR/OATutor)

### 交互界面

桌面布局建议：左边课程地图与待复习，中间原课件/图像/公式，右边导师与答题区域。小屏改为标签切换。

每次只突出当前目标和一个待答问题，保留“再讲直觉 / 给提示 / 看推导 / 独立练习 / 暂缓”入口。题解默认折叠，作答与评分放独立卡片；选中某个公式可以局部追问，不打断主路径。记录同步只用状态图标，故障时才显式提示。

Obsidian 保存原资料、导出笔记与可读进度。若另建系统，数据库或结构化状态应作为唯一学习状态来源，Markdown 为导出视图，避免两个系统同时改进度。

## 现成工具如何选

| 路线 | 适用理由 | 仍需解决 |
|---|---|---|
| RemNote Guided Learn | 文档/文件夹可启动学习，原文、问答、测验与掌握跟踪联系紧密 | 未证实多课件会自动融合成先修图；需要检查推导题体验 |
| DeepTutor Mastery Path | 官方描述多材料路径、遗漏文件提示、掌握检查、复习和恢复 | 用户已遇到读取 bug；多材料选择不等于跨文档教学，必须实际回归 |
| OpenMAIC | 互动课堂、白板、仿真与课件体验适合物理直觉 | 未确认可靠的长期跨课件掌握调度；生成课堂可能增加等待 |
| Open WebUI + 自建课程状态 | 现成聊天壳、资料能力、独立任务模型和后台子代理 | 不自带本场景所需的课程地图与学习证据规则 |
| Chainlit + LangGraph + 持久数据库 | 可较快验证题卡、侧边资料、流式响应与可恢复状态 | 属于开发框架，仍需编写课程规划、解析、调度与交互 |

RemNote 官方还明确：初始熟悉度选择改变学习活动优先顺序，内容本身不变。因此不能把它直接视为完整自适应课程系统。[Guided Learn](https://help.remnote.com/en/articles/15724936-guided-learn-mode)

DeepTutor 官方功能范围见 [Mastery Path](https://docs.deeptutor.info/explore/mastery-path/) 与 [Task Model 设置](https://docs.deeptutor.info/explore/settings/)。文档描述不能代替用户实际体验与验收。

OpenMAIC 的功能与版本需对照 [官方仓库](https://github.com/THU-MAIC/OpenMAIC)；主分支可能包含预发布特性。Open WebUI 的 [Task Models](https://docs.openwebui.com/features/administration/task-models/) 主要服务标题、标签等辅助任务，不能据此断言学习记忆已自动异步化；[后台子代理](https://docs.openwebui.com/features/chat-conversations/chat-features/subagents/) 可作为扩展基础。Chainlit 提供 [自定义交互元素](https://docs.chainlit.io/api-reference/elements/custom) 与 [流式输出](https://docs.chainlit.io/advanced-features/streaming)，适合小范围原型。

更多产品核查见同目录 framework-research.md，包括 NotebookLM 与 LearnHouse；前者偏资料阅读，后者偏课程组织，本次不作为首选主系统。

## 推荐的验证顺序

1. 保留现有资料和学习证据，用同一组材料试 RemNote，先评估日常学习界面。不要因为 UI 顺手就直接迁移所有笔记。
2. DeepTutor 只在愿意再次排查时复测：先让全部文件可靠可读，再测路径融合。解析层失败时无需继续评估教学质量。
3. 如“跨文档先修调度”仍不达标，做一个范围明确的原型：覆盖波函数→本征态→投影→作业第 7 题；实现前台教师、后台记录、知识点状态和来源侧栏。先验证这一条跨文件链，再扩到 8 份材料。

验收指标：

- 8 份材料都有解析结果或明确错误；抽查原图、公式与来源定位。
- 知识点—页码—习题小问可互查；重复概念合并，暂缓内容可见。
- 重复追问会触发补救；“继续”和看过答案不会自动提高掌握等级。
- 中断重开后，当前任务、未解疑问、作答证据仍一致。
- 同一模型、网络与材料下，分别测首个有效内容时间、完整答案时间、工具等待与后台完成时间；用多轮中位数和慢请求分位数比较，不凭单次体感。
- 后台失败不阻塞下一次讲解，重试不重复写入；旧记忆不会盖过新回答。

本轮交付研究和设计建议，未修改原学习笔记，也未安装或切换学习系统。
