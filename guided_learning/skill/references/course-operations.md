# Course operations

Run `guided-learning --course <course-name> --request <request.json>`. Course names use lowercase letters, digits and hyphens (`quantum-v1`) and resolve inside the course library; `guided-learning courses` prints the library `root` and each course's `name`, `title`, source count and review backlog. `--workspace <directory>` addresses a course outside the library instead. The request file is UTF-8 JSON; omit `--request` to read JSON from stdin. Exit 0 returns `{ "ok": true, "result": ... }`; exit 1 returns `{ "ok": false, "error": { "code": ..., "message": ... } }`.

## Creating a course

1. Get the learner's files and goal. If either is missing, explain in a few lines: attach the files or name their folder, and say what they want to learn. Attachments may arrive as local paths; if a file's content is visible but not its path, ask where it is saved, or ask the learner to put it in `<root>/<course-name>/inputs/`.
2. Propose a short course name from the files and goal, and check it is not already listed by `guided-learning courses`.
3. Always interview the learner before building the route, even when the goal seems clear, in one short message in their language. Skim the files first so the questions are specific to them. Ask, offering choices they can answer in a word:
   - **Goal:** what they want to be able to do, and by when (an exam on a date, a project, general understanding).
   - **Prior knowledge:** list the three to six prerequisites these materials actually assume (for example "complex numbers", "linear algebra: eigenvalues", "Fourier transforms") and ask for each: none, some, or solid.
   - **Depth:** overview (intuition and key results), standard (main derivations and worked examples), or rigorous (proofs, conditions and edge cases).
   - **Focus:** anything to emphasize or skip, such as problem-solving for the exam, or chapters they already know.
   Accept partial answers and use sensible defaults for the rest; do not ask a second round unless an answer changes the route a lot. Save the answers with `course.profile.save` after `course.init`.
4. Copy the learner's files into `<root>/<course-name>/inputs/`, keeping the originals. Sources are identified by absolute path, so register these stable copies, not files in Downloads or a temporary folder.
5. Run `course.init`, then `course.profile.save`, then `preferences.save` with the teaching language when the learner writes in a supported language other than English, then `source.register` for each copy.
6. Build the route chapter by chapter (see curriculum operations) to fit the profile: add short foundation sections for prerequisites marked none that the goal needs, start later for solid ones, and order by the goal (exam topics first when there is a deadline). Before `curriculum.outline`, show the chapter outline in a few lines, with the first chapter's sections and how it reflects their answers, and adjust if they object. Once they agree, build the chapters without asking again.
7. Open the course in the app with `guided-learning open <course-name>` as soon as the first chapter is built, then build the rest, unless the learner prefers to let the app build the outlined chapters as they study (see curriculum operations).

## Requests

- `{"op":"course.init","title":"Quantum"}` creates a course; reopening via init preserves the existing title and state.
- `{"op":"course.status"}` returns `course`, `position`, `sources` and `profile`.
- `{"op":"course.profile.save","profile":{"goal":"Pass the final on 15 Jan","depth":"standard","prerequisites":[{"topic":"Complex numbers","level":"solid"},{"topic":"Fourier transforms","level":"none"}],"focus":"Exam-style problems"}}` saves the learner profile from the interview, replacing any earlier one. `depth` is `overview`, `standard` or `rigorous`; levels are `none`, `some` or `solid`; `focus` and `notes` are optional. The app's teacher reads it for every lesson. It records what the learner reported, never mastery. Save again when the learner changes their mind.
- `{"op":"preferences.save","language":"zh-CN"}` sets the course's teaching language: `en` (default) or `zh-CN`. The app teaches new lessons, answers, exercises and preparation in it; the learner can change it in Settings. `preferences.view` reads it, along with `daily_reviews` (the most review questions a day, default 5), which the learner sets in Settings; `preferences.save` changes only the fields it is given.
- `{"op":"source.register","path":"/absolute/path/slides.pdf"}` returns `source` containing stable `id`, normalized `path`, SHA256 `revision`, `status`, `verification`, and `errors`. Repeat after a file changes. Missing files stay visible with a failed latest registration; an earlier revision remains readable. A successful registration means the attempt was recorded, not necessarily that extraction succeeded.
- `{"op":"source.read","source_id":"src-..."}` returns the latest available snapshot with `units`, `status`, `errors`, and `verification`; pass `revision` to retrieve a previous snapshot. Each unit has stable within-revision `id`, `locator` and `text`. Markdown uses `{ "line": 1 }`, PDF uses `{ "page": 1 }`. PDF empty/image-only pages are `needs_review`.
- `{"op":"position.save","request_id":"checkpoint-1","position":{"goal":"Understand normalization","progress":"Introduced probability density","next_step":"Normalize the example"}}` saves a minimal mainline position object.
- `{"op":"annotations.list","concept_id":"optional-section"}` returns the learner's `annotations` (highlights, notes and bookmarks), oldest first. They are private to the learner: read them only when the learner asks about their own notes, never as teaching context or evidence (ADR 0005). `annotations.save` (`id`, `kind`, and `passage` (with `occurrence`, which repeat of it in its text, 0 for the first), `note` and one of `turn_id` (lesson or side-question answer), `task_id` (exercise), `source` or `concept_id`; an existing `id` only updates `note`) and `annotations.delete` (`id`) exist for the app; change annotations only when the learner asks.

`verification: pending` means formulas, images and page mapping have not been independently checked. Source units are extraction units, not a completed coverage ledger. A Markdown line must not be presented as a PDF page.

## Storage and extension contract

The workspace contains `course.sqlite3` and `sources/<source-id>/<sha256>` byte snapshots. Use operations instead of editing the database. Source identity follows normalized absolute path; moving a source registers a new identity. Keep a stable input location for revisions.

Python callers use `guided_learning.execute(workspace, request)`; validation errors raise `OperationError` with `.code`. Each request holds one SQLite transaction: `BEGIN IMMEDIATE` for a write, a deferred read-only one for operations listed in `guided_learning.api.READS`. An exception rolls it back. Operation modules export `OPERATIONS = {"operation.name": handler}`; add the module name to `guided_learning.api.MODULES`. Handlers take `(store, request)` and return JSON-serializable results. `store.get(namespace, key, default=None)`, `put(namespace, key, value)`, `list(namespace)` and `delete(namespace, key)` read/write JSON documents; reserve a separate namespace for each feature. `store.db` is available when relational constraints are needed. Handlers must not commit or close the shared transaction.

Core namespaces: `course` (`metadata`, `position`, `schema`: the course format version, which operations migrate forward and never write by hand), `sources` (key: source ID), `source_revisions` (key: `<source-id>:<revision>`). Preserve old snapshots and user learning evidence when building on source changes. Reading a snapshot may use a cached earlier revision even when the newest registration failed; consult source status as well.

Checkpoint writes (`position.save` and `mainline.enter`) require a unique nonempty `request_id` for each intended change. Reuse the same ID only for an identical retry. A retry returns `replayed:true`, the **current** `position`, and the first response under `original_result`; it never restores that old position. Changed contents under an existing ID are rejected. Use `session.resume` for current due items after a replay. Existing databases remain readable; update older calling scripts to supply IDs.
